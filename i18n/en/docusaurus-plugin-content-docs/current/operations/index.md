# Participate through Sphere-DOS

Sphere-DOS provides four surfaces: workspace expansion, a .vendor submodule, a PLI Context Alias, and Fork-on-Live or Dev Container. Choose the workbench required for the task and begin with the Manifest and consuming repository's policies.

A Prompt Line Interface receives intent, context, and constraints. A Command Line Interface receives commands and arguments. Neither is a fake version or a universal replacement for the other.

Check a GitHub connector, Python process, Codespaces, or model provider separately as an Execution Envelope. Reading documentation is distinct from executing the CLI, MAGI resolver, or tests.

1. Resolve the Manifest, target repository, and adopted main revisions.
2. Read local AGENTS and specifications.
3. State purpose, sources, authority, output, and stopping conditions.
4. Repair resolvable differences with a record; return unresolved meaning, authority, or provenance conflicts to existing issues.
5. Separate completed checks from unexecuted checks and retain the main change and recovery path.

Follow the Sphere-DOS source for bootstrap commands and Native Surfaces. This English page is an explanation, not an equivalent executable Kernel translation.
